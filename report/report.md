## 1. Введение и постановка задачи

**Задача:** предсказать длину текстового сообщения в символах. Формально — регрессия, целевая переменная `message_length = len(text)`.

Датасет изначально для sentiment analysis. Задача прикладная: оценка ожидаемой длины нужна, например, для предварительной фильтрации контента или адаптации интерфейсов под платформу.

**Метрика — MAE.** RMSE считаю дополнительно, потому что Reddit-комментарии бывают очень длинными и хочется видеть, как модель реагирует на выбросы. R² — чтобы сравнить с константным предсказанием.

## 3. Обработка и подготовка данных

**Очистка:**

| Проблема | Кол-во | Действие |
|----------|--------|----------|
| Пропуски в `text` | 104 | Удалил — без текста цель не посчитать |
| Пустые строки | 122 | Удалил |
| Пропуски в `category` | 7 | Оставил, добавил флаг `sentiment_missing` |
| Дубликаты (`text` + `platform`) | 452 | Удалил **до** сплита |
| Экстремально длинные | — | 99.5-й перцентиль, граница 944 символа |

Осталось **198 770 строк**. Типы: `text → string`, `category → float`, `message_length` и счётчики → `int`.

**Feature Engineering** (целевую считаю первой, чтобы не было утечки):

| Признак | Тип | Что это |
|---------|-----|---------|
| `word_count` | int | Число слов |
| `unique_word_count` | int | Уникальных слов |
| `avg_word_length` | float | Средняя длина слова |
| `unique_word_ratio` | float | Доля уникальных |
| `digit_count` | int | Число цифр |
| `digit_ratio` | float | Доля цифр в символах |
| `has_digits` | int | Есть ли цифры (0/1) |
| `sentiment_missing` | int | Флаг пропуска в category |

Корреляция `word_count` с длиной — **0.989**, `category` с длиной — **0.053**. Это уже намекает, что произойдёт в финальной модели.

## 4. Baseline

`LinearRegression` на трёх полях из исходного датасета — без какого-либо feature engineering.

Признаки: `category`, `platform`, `sentiment_missing`.

| MAE val | RMSE val | R² val | MAE test | RMSE test | R² test |
|---------|----------|--------|----------|-----------|---------|
| 68.503 | 91.779 | 0.006 | 68.185 | 90.824 | 0.006 |

R² ≈ 0 — не лучше среднего. Тональность и платформа сами по себе про длину ничего не знают.

---

## 5. Эксперименты

Обучение на train, подбор гиперпараметров по val, финальное сравнение на test. Критерий выбора — MAE на val.

---

### Эксперимент 1: помогает ли feature engineering линейной модели?

**Гипотеза:** `word_count × avg_word_length` почти и есть длина арифметически, значит линейная модель на новых признаках должна сильно обойти baseline.

**Как проверялось:** та же `LinearRegression`, но на 10 engineered features вместо 3.

**Результат:**

| | MAE val | MAE test | R² test |
|--|---------|----------|---------|
| baseline | 68.503 | 68.185 | 0.006 |
| LinearRegression (engineered) | 5.805 | 5.773 | 0.989 |

В 12 раз лучше. Признаки работают.

---

### Эксперимент 2: Ridge

**Гипотеза:** `word_count` и `unique_word_count` коррелируют, Ridge должна стабилизировать решение.

**Как проверялось:** перебор alpha ∈ {0.1, 1, 10, 30}.

**Результат:**

| Модель | alpha | MAE val | MAE test |
|--------|-------|---------|----------|
| LinearRegression | — | 5.805 | 5.773 |
| Ridge | 30 | 5.803 | 5.771 |

Разница в третьем знаке. Признаков мало, регуляризация не нужна.

---

### Эксперимент 3: деревья и бустинг

**Гипотеза:** нелинейные модели поймают случаи, где `length ≠ word_count × avg_word_length` (короткие слова, специфические паттерны).

**Как проверялось:** `RandomForest`, `ExtraTrees`, `GradientBoosting` — по 2–4 варианта гиперпараметров каждый.

**Результат:**

| Модель | Параметры | MAE val | MAE test | RMSE test |
|--------|-----------|---------|----------|-----------|
| Ridge | alpha=30 | 5.803 | 5.771 | 9.681 |
| **RandomForest** | depth=None, leaf=1, n=180 | **0.075** | **0.065** | 1.189 |
| ExtraTrees | depth=30, leaf=1, n=220 | 0.089 | 0.083 | 1.684 |
| GradientBoosting | lr=0.05, depth=5, n=220 | 0.454 | 0.445 | 1.066 |

RandomForest лучший по MAE. GBR неожиданно выиграл по RMSE, но не по основной метрике.

---

### Эксперимент 4: VotingRegressor

**Гипотеза:** ансамбль Ridge + ExtraTrees + GBR сгладит ошибки лучше одиночной модели.

**Как проверялось:** `VotingRegressor` с лучшими параметрами каждой из трёх моделей.

**Результат:**

| Модель | MAE val | MAE test |
|--------|---------|----------|
| RandomForest | 0.075 | 0.065 |
| VotingRegressor | 1.971 | 1.960 |

Хуже. Когда одна модель сильно лучше других — усреднять не надо.

---

### Эксперимент 5: TF-IDF vs. tabular features + уменьшение размерности

**Гипотеза:** raw текст через TF-IDF должен работать хуже явных структурных признаков. TruncatedSVD поверх TF-IDF дополнительно потеряет информацию.

**Как проверялось:** `TF-IDF + Ridge` (bigrams, min_df=5, max_features 3k/5k) и `TF-IDF + TruncatedSVD + Ridge` (n_components ∈ {50, 100, 200}).

**Результат:**

| Модель | MAE val | MAE test | R² test |
|--------|---------|----------|---------|
| TF-IDF + Ridge | 26.170 | 25.837 | 0.789 |
| TF-IDF + SVD(200) + Ridge | 40.099 | 39.491 | 0.584 |
| RandomForest (tabular) | **0.075** | **0.065** | 0.99983 |

TF-IDF проиграл в 400 раз. SVD ещё ухудшил — 200 компонент объясняют только 27.5% дисперсии матрицы, мешок слов не несёт информацию о длине эффективно.

## 6. Финальная модель и интерпретируемость

**Выбор:** `RandomForestRegressor` — лучший MAE на val (0.075) и на test (0.065). После выбора конфигурации переобучен на train+val.

Параметры: `n_estimators=180, max_depth=None, min_samples_leaf=1`

| MAE test | RMSE test | R² test |
|----------|-----------|---------|
| 0.055 | 1.147 | 0.99984 |

**Важность признаков:**

| Признак | Важность |
|---------|----------|
| `word_count` | 0.9803 |
| `avg_word_length` | 0.0196 |
| остальные 8 | < 0.001 суммарно |

![](images/final_model_feature_importance.png)

`length ≈ word_count × avg_word_length + (word_count − 1)` — это арифметика, не ML. Модель выучила формулу. Высокие метрики объясняются постановкой задачи, а не сложностью модели.

## 8. Заключение и выводы

**Итоги:** без feature engineering MAE = 68.2 (хуже среднего). С engineered features линейная модель даёт MAE = 5.8, RandomForest — 0.055. TF-IDF проиграл в 400 раз: для предсказания длины мешок слов не работает.

**Ограничения:** постановка задачи оказалась почти детерминированной — `word_count` и `avg_word_length` напрямую кодируют цель. Поэтому цифры красивые, но задача несложная. Датасет содержит только очищенные тексты, без эмодзи, хэштегов и ссылок — эти признаки могут быть информативны на реальных данных.

**Возможные улучшения:** убрать `word_count` и `avg_word_length` из признаков — тогда задача станет честной. Добавить признаки пунктуации и заглавных букв. Сравнить модели отдельно для Twitter и Reddit.
